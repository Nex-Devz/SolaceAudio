Documentation / v1.0.32

Configuration, endpoints, and the parts that bite.

Everything on this page describes version 1.0.32 of the plugin and assumes a Lavalink v4 node with a writable working directory.

Requirements

  • Java 17 or newer. The build targets Java 17 bytecode.
  • Lavalink v4.0 or later. v4.2.x server distributions are supported.
  • A writable working directory if you enable the local disk cache.
  • Outbound HTTPS to the source APIs you enable, plus JitPack on the first boot that resolves the plugin.
  • No database, sidecar process or native audio tooling.

Upgrading from 1.0.25 or earlier? Those builds required Micrometer on the classpath and could fail with NoClassDefFoundError: io/micrometer/core/instrument/MeterRegistry. From 1.0.26 the plugin binds to Lavalink's actuator registry only when it is present.

Install

Add the plugin and the official YouTube source to application.yml. SolaceAudio detects the official source at startup and layers its metadata repair, mirror fallback and disk cache on top.

application.yml 
lavalink:
  defaultPluginSnapshotRepository: "https://maven.lavalink.dev/snapshots"
  plugins:
    - dependency: "com.github.Nex-Devz.SolaceAudio:solaceaudio-plugin:1.0.32"
      repository: "https://jitpack.io"

    # The official YouTube source. SolaceAudio wraps and enhances it.
    - dependency: "dev.lavalink.youtube:youtube-plugin:2be8e542d3f6f178e048dca565892684c2e40177"
      snapshot: true

Start the node the same way you always have. SolaceAudio registers its managers during startup and logs the sources it adds.

Start and verify 
# start Lavalink
java -jar Lavalink.jar

# load a track through the v4 loader
curl -G "http://localhost:2333/v4/loadtracks" \
  --data-urlencode "identifier=spsearch:Bohemian Rhapsody" \
  -H "Authorization: youshallnotpass"

About the YouTube snapshot. The 1.18.x release line of the official plugin still ships InnerTube client versions that YouTube rejects with HTTP 400. The pinned snapshot above carries current client versions. Replace it with the release you trust, or set youtube.nativeSource: true to run SolaceAudio's own YouTube source instead.

YouTube & datacenter IPs

Cloud IP ranges are watched more closely than residential ones. Four settings do most of the work on a hosted node: a burner cookie, a PoToken endpoint, mirroring, and the local cache.

plugins.solaceaudio.youtube 
youtube:
  oembed: true
  mirror: true
  mirrorProviders: []          # empty uses the built-in cross-service list
  nativeSource: false       # true runs SolaceAudio's own YouTube source
  localDiskCache: true
  diskCachePath: "youtube-cache"
  maxDiskCacheMb: 10240
  cipherUrl: "https://cipher.kikkia.dev"
  cookieFile: "ytburner.txt"
  potokenUrl: "https://potoken-generator.vercel.app/token"

Burner cookie

Place a Netscape-format cookie file in the Lavalink working directory and name it in cookieFile. SolaceAudio uses it to compute rolling SAPISIDHASH authorization headers in memory for WEB_REMIX requests.

PoToken

A Proof-of-Origin token lifts bot checks on requests that would otherwise return 403. Point potokenUrl at the managed generator, or deploy an isolated generator to your own infrastructure from the potoken-generator template.

Mirroring and the cache

With mirror: true, a blocked direct stream triggers a resolution pass across the mirror ladder. mirrorProviders is empty by default, which uses the built-in cross-service list: Spotify, Deezer, JioSaavn, Apple Music and Amazon Music.

The disk cache streams audio to disk through transactional .part files and evicts least-recently-used entries at the quota. Ten gigabytes is a reasonable starting point for a busy public bot. Lower it, or set localDiskCache: false, when storage is tight.

Mid-stream failures

When a stream URL expires or starts returning 403, 429 or 401, the producing client is cooled down for 60 seconds and another client in the pool resolves a fresh stream. The cache entry is invalidated rather than replayed.

Security note. Runtime cipherUrl updates are validated against loopback, private subnets and cloud metadata addresses before they are applied. Cache paths are normalised and checked against their parent directory.

Configuration

The full plugin block. Every key below is read at startup; a subset can be changed at runtime through PATCH /v4/SolaceAudio/config.

Sources and the ladder

plugins.solaceaudio 
plugins:
  solaceaudio:
    # Skip PCM conversion when no DSP filters are active.
    passthrough: false

    sources:
      spotify: true
      applemusic: true
      youtube: true
      deezer: true
      jiosaavn: true
      gaana: true
      amazonmusic: true
      pandora: true
      audiomack: true
      shazam: true
      flowerytts: true

    # Tried in order. Reorder, remove or extend freely.
    providers:
      - "spsearch:\"{isrc}\""
      - "spsearch:{query}"
      - "dzisrc:{isrc}"
      - "dzsearch:{query}"
      - "ytsearch:\"{isrc}\""
      - "ytsearch:{query}"
      - "jssearch:\"{isrc}\""
      - "jssearch:{query}"
      - "azsearch:{query}"
      - "scsearch:{query}"
      - "bcsearch:{query}"

Keys worth changing first

KeyDefaultEffect
providersISRC-first ladderOrder in which mirrors are attempted. Remove a provider your host cannot reach.
jiosaavn.quality320kbpsDrop to 160kbps to halve node bandwidth with little perceived loss.
maxDiskCacheMb10240Disk cache quota. LRU entries are evicted when the limit is reached.
passthroughfalseDeliver raw Opus frames when no DSP filter is active. Lower CPU, no transcoding.
mirrortrueResolve an alternative source when direct YouTube playback is refused.
lyrics.enabledtrueEnable the four-provider lyrics routes and the per-player lyrics endpoint.

Search prefixes

Prefixes are the portable form: they work from any Lavalink client, and the same string can sit in the mirror ladder. Native share URLs are also accepted by the source handlers.

SourcePrefixNotes
Spotifyspsearch:ISRC queries with spsearch:"{isrc}" resolve precisely.
Apple Musicamsearch:Falls back to the public iTunes Store API when the storefront token fails.
YouTubeytsearch: ytmsearch:Search only. Video and playlist IDs load directly.
Deezerdzsearch: dzisrc:dzisrc: performs an exact ISRC lookup.
JioSaavnjssearch:Bitrate follows jiosaavn.quality.
Gaanagnsearch: gaanasearch:Both spellings are registered.
Amazon Musicazsearch: amazonsearch:Native MESK catalog with proxy fallback.
Audiomackadmsearch:Songs, albums and playlists through the signed API.
Pandorapdsearch:Adaptive AAC streams.
Shazamshsearch: szsearch:Discovery metadata, then resolution through the ladder.
FloweryTTSftts: speak: tts:Text-to-speech through the public neural endpoint.
SoundCloud / Bandcampscsearch: bcsearch:Provided by Lavalink's built-in sources, not SolaceAudio.

Load a track with any prefix through the standard loader:

GET /v4/loadtracks?identifier=jssearch:Kesariya

REST API

All routes inherit the Lavalink server's authorization. Send the same password you use for the rest of the v4 API.

Endpoints

MethodRoutePurpose
GET/v4/lyricsLyrics by track, artist and optional duration.
GET/v4/lyrics/searchFuzzy multi-provider search with query.
GET/v4/sessions/{sessionId}/players/{guildId}/lyricsLyrics for the active track in a guild player.
GET/v4/sessions/{sessionId}/players/{guildId}/recommendationRecommendations from the active player. Optional limit.
GET/v4/sessions/{sessionId}/players/{guildId}/sponsorblockKnown SponsorBlock segments for the current track.
POST/v4/sessions/{sessionId}/players/{guildId}/sponsorblockUpdate enabled categories for the guild.
PATCH/v4/SolaceAudio/configRuntime updates for supported configuration keys.
GET/v4/SolaceAudio/youtube/suggestSearch suggestions with query or q.

Client-library compatibility aliases are registered for /recommendations and /sponsorBlock, and both casings of /v4/SolaceAudio resolve.

Running LavaLyrics alongside SolaceAudio? Since 1.0.32, LyricsController and SolaceLyricsManager carry @ConditionalOnMissingClass and @ConditionalOnProperty. When lavalyrics-plugin is present, SolaceAudio yields the /v4/lyrics routes to it instead of throwing a Spring Ambiguous mapping error, and keeps feeding its providers — LRCLIB, Deezer, Genius and Spotify — into LavaLyrics.

Lyrics lookup

curl -G "http://localhost:2333/v4/lyrics" \

Build from source

JDK 17 is required. The project is a multi-module Gradle build: solaceaudio-main carries the source managers and solaceaudio-plugin adds the Lavalink wiring and REST controllers.

shell 
git clone https://github.com/Nex-Devz/SolaceAudio.git
cd SolaceAudio

# Windows
gradlew.bat build

# Linux / macOS
./gradlew build

The jar lands in plugin/build/libs/. When the VERSION environment variable is set, it is named solaceaudio-plugin-<version>.jar. Without it, Gradle falls back to dev, which is expected for local builds.

Run the suite with ./gradlew test. The v1.0.32 tree carries 65 unit and integration tests, including the Audiomack and Shazam source managers.

Troubleshooting

YouTube returns 403 or 429

  1. Place a burner cookie file in the Lavalink root and set cookieFile.
  2. Enable potokenUrl so requests carry a fresh Proof-of-Origin token.
  3. Keep mirror: true so playback can resolve from another source.
  4. If the node is on a heavily flagged range, route YouTube traffic through a residential proxy.

The disk cache is growing too large

Lower maxDiskCacheMb under plugins.solaceaudio.youtube. SolaceAudio evicts least-recently-used entries once the quota is reached. Setting localDiskCache: false disables the cache entirely.

The release jar is named solaceaudio-plugin-dev.jar

Gradle uses dev when no VERSION is set. The release workflow derives the version from the pushed tag. For a custom build, export VERSION=1.0.32 before building.

A source prefix returns nothing

Confirm the source is enabled under plugins.solaceaudio.sources, then try the prefix directly through /v4/loadtracks. Some sources depend on public endpoints that can rate-limit or change; the mirror ladder exists so one failure does not stop the queue.

Lyrics come back empty

Check lyrics.enabled and the route you are calling. The endpoint returns 404 when no provider has a match, which is normal for obscure or unreleased tracks. The per-player route resolves from the active track metadata instead of a text query.

Still stuck?

Open an issue with the plugin version, Lavalink version, Java version, host provider, the source prefix that failed, and the relevant log lines. Redact cookies, ARL values and tokens before posting. See the issue tracker or the Discord.
