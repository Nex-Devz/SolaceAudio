01 / Failure modes

Production nodes fail in three predictable ways.

SolaceAudio was built around those failures, not around a feature list. Each subsystem exists because a node went down without it.

01

Datacenter IPs get rejected

YouTube challenges player requests from Hetzner, OVH and other cloud ranges. SolaceAudio computes rolling SAPISIDHASH headers, rotates InnerTube clients, and rebuilds direct-link metadata over oEmbed when the player endpoint refuses.

  • SAPISIDHASH
  • PoToken routing
  • Client rotation
  • oEmbed repair
02

Mass queue additions hammer upstreams

When a hundred listeners queue at once, duplicate searches leave at the same moment. Lock-free atomic futures coalesce identical in-flight queries, so one upstream request serves the whole burst.

  • Single-flight
  • Lock-free futures
  • Deduplication
03

Mirrors pick the wrong track

Covers, slowed edits and music-video rips all match a title. Candidates are filtered by duration, penalised for live, acoustic, cover and karaoke terms, then scored with Levenshtein distance. A shared ISRC wins outright.

  • ISRC 1.0
  • ±2s window
  • Penalty vectors

03 / Resolution

Ask once. Walk the ladder. Keep the best match.

Every external track is resolved through an ordered provider list. The default ladder works without configuration. Reorder it in application.yml when your traffic knows better.

  1. 01

    Exact ISRC

    A shared ISRC is the strongest signal available. Catalog-exact lookups run before any free-text search.

    spsearch:"{isrc}" dzisrc:{isrc} ytsearch:"{isrc}" jssearch:"{isrc}"
  2. 02

    Sanitized query

    Noise tags are stripped and Unicode is preserved, so a Devanagari or Cyrillic title does not collapse into an empty search string.

    spsearch:{query} dzsearch:{query} ytsearch:{query} jssearch:{query} azsearch:{query} admsearch:{query} shsearch:{query} qbsearch:{query} tdsearch:{query}
  3. 03

    Last resort

    SoundCloud and Bandcamp catch the remainder. If a provider is down, the next one is already waiting.

    scsearch:{query} bcsearch:{query}
  4. 04

    When a direct URL is blocked

    Metadata is rebuilt through oEmbed, then the same ladder resolves a playable alternative. The listener sees one track; the node quietly changes where it comes from.

    oembed mirror: true disk cache
Candidate scoring Deterministic
  • ISRC match 1.00
  • Levenshtein distance normalized
  • Duration delta ±2 seconds
  • Penalty terms live · cover · slowed
  • Noise tokens stripped

Penalties only apply when the term is absent from the source title. An acoustic recording labelled as such is not punished for saying so.

The ladder, cache quota, pass-through mode and per-source load limits are all runtime configuration. No recompilation required.

04 / Subsystems

The work is in the parts you never see.

Caching, CPU and failure handling are not side features here. They are the reason the queue stays up at 3 a.m.

01

Atomic disk cache

Streams pass through to disk with transactional .part swaps. Repeat plays start instantly, and the least recently used track is evicted at the quota.

02

Zero-transcode Opus

With no active DSP filters, WebM Opus frames go straight to Discord. The project reports roughly 60% less CPU on that path.

03

Single-flight coalescing

Identical searches already in flight share one upstream request instead of multiplying it across the thread pool.

04

Voice ducking and silence trim

A 32-bit float filter ramps music down during voice activity and trims lead-in dead air with an exponential moving average detector.

05

Synchronized lyrics

LRCLIB, Deezer, Genius and Spotify are merged into timestamped LRC or plain text through one endpoint, with no API keys required.

06

Native SponsorBlock

Non-music segments are skipped using the official API, with a bounded TTL cache and per-category control through REST.

07

Mid-stream client rotation

A client that returns 403 or 429 is cooled down for 60 seconds while another takes over. Playback does not stop waiting.

08

Prometheus metrics

Client requests, mirror resolutions, cache hits and live filter gauges are exported through Lavalink's actuator registry.

05 / Install

One dependency, then get on with the bot.

The plugin does not replace Lavalink. It registers sources, wraps the YouTube source, and adds the routes below. No database, sidecar or build step.

  1. 1

    Add the dependency

    Paste both entries into application.yml. The pinned YouTube snapshot carries InnerTube client versions that YouTube currently accepts.

  2. 2

    Start the node

    SolaceAudio registers its sources during startup. Watch the log for the source list, then send a track from any source prefix.

  3. 3

    Tune for your host

    On a datacenter IP, add a burner cookie and a PoToken endpoint. If your community repeats tracks, raise the disk cache quota.

# lavalink/application.yml
lavalink:
  defaultPluginSnapshotRepository: "https://maven.lavalink.dev/snapshots"
  plugins:
    - dependency: "com.github.Nex-Devz.SolaceAudio:solaceaudio-plugin:1.0.34"
      repository: "https://jitpack.io"

    # Official YouTube source. SolaceAudio layers oEmbed repair,
    # mirror fallback and disk caching on top of it.
    - dependency: "dev.lavalink.youtube:youtube-plugin:2be8e542d3f6f178e048dca565892684c2e40177"
      snapshot: true
// build.gradle.kts
repositories {
    mavenCentral()
    maven("https://jitpack.io")
    maven("https://maven.lavalink.dev/releases")
}

dependencies {
    implementation("com.github.Nex-Devz.SolaceAudio:solaceaudio-main:1.0.34")
}
<!-- pom.xml -->
<repository>
  <id>jitpack.io</id>
  <url>https://jitpack.io</url>
</repository>

<dependency>
  <groupId>com.github.Nex-Devz.SolaceAudio</groupId>
  <artifactId>solaceaudio-main</artifactId>
  <version>1.0.34</version>
</dependency>

On the YouTube snapshot: the 1.18.x release line still ships client versions YouTube rejects with HTTP 400. Pin the snapshot you trust, or set youtube.nativeSource: true to use the built-in source instead.

07 / Control surface

Endpoints for the parts Discord does not show.

Recommendations, lyrics and SponsorBlock are exposed over Lavalink's REST server and inherit its authorization. The routes below are current for v1.0.34.

GET /v4/solace/health Node health: uptime, JVM memory, sessions and registered sources.
GET /v4/lyrics?track={title}&artist={artist}&duration={ms} Metadata lookup with timestamp alignment.
GET /v4/lyrics/search?query={query} Fuzzy search across all four lyrics providers.
GET /v4/sessions/{sessionId}/players/{guildId}/lyrics Lyrics for the track currently in a guild player.
GET /v4/sessions/{sessionId}/players/{guildId}/recommendation?limit=10 Contextual autoplay from the active player buffer.
GET /v4/sessions/{sessionId}/players/{guildId}/sponsorblock Segments for the current YouTube track.
POST /v4/sessions/{sessionId}/players/{guildId}/sponsorblock Update enabled categories for the guild.
PATCH /v4/SolaceAudio/config Live source limits, JioSaavn quality and YouTube cache settings.
GET /v4/SolaceAudio/youtube/suggest?query={query} YouTube search suggestions for command autocomplete.

08 / Questions

The things people ask after the first 403.

Operational answers, not marketing ones. If your case is not here, the issue tracker is the next stop.

YouTube returns 403 or 429. Where do I start?

Datacenter ranges are monitored aggressively. Add a burner cookie file to the Lavalink working directory and set cookieFile, enable potokenUrl, and keep mirror: true so SolaceAudio can resolve alternative streams when direct playback is restricted. A residential proxy is the fallback, not the first move.

Do I need Spotify or Deezer credentials?

No. Spotify negotiates an anonymous token and Deezer streams publicly at 128 kbps without an ARL. Optional credentials raise the ceiling: a Deezer ARL unlocks 320 kbps and FLAC, and a Spotify sp_dc cookie adds Canvas, synchronized lyrics and personalised playlists.

Will this run on a small VPS?

It runs inside the Lavalink process you already pay for, so the added memory is modest. The real local cost is the disk cache. Cap it with maxDiskCacheMb, or disable localDiskCache when storage is tight. Mirroring adds outbound bandwidth, not CPU.

Which Lavalink and Java versions are supported?

Java 17 or newer, and Lavalink v4.0 and later, including v4.2.x server distributions. The plugin is compiled against the v4 API and does not pull Micrometer into the runtime, so stock Lavalink distributions load it without actuator dependencies.

Is a database required?

No. The disk cache is a directory of files with transactional .part swaps. Memory caches are bounded and TTL-driven. Nothing to migrate, back up or vacuum.

How do updates work?

Bump the dependency version in application.yml and restart. JitPack builds each tagged release, and the GitHub releases page carries the versioned plugin jar. There is no client SDK to update alongside it.

Can I use the built-in YouTube source instead of the official plugin?

Yes. Set youtube.nativeSource: true under plugins.solaceaudio. SolaceAudio then registers its own YouTube source. If you keep the official plugin, SolaceAudio detects it at startup and layers oEmbed repair, mirror fallback and disk caching on top.
